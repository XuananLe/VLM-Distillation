\chapter{Evaluation Methodology}
\label{chap:evaluation-methodology}

\section{Experimental Setup}
All experiments follow a shared evaluation protocol for fair comparison across methods.

The study focuses on two compact student models, \textbf{SmolVLM-500M} and \textbf{SmolVLM-256M}, evaluated on text-rich multimodal benchmarks \cite{marafioti2025smolvlm}.

All model evaluations are conducted using \textbf{VLM-Eval-Kit} \cite{duan2024vlmevalkit}. In brief, the toolkit works as follows:
\begin{enumerate}
\item Load a benchmark split and apply its prompt template or input format.
\item Run model inference through a unified model wrapper interface.
\item Post-process raw generations into normalized answers.
\item Compute dataset-specific scores (e.g., VQA Accuracy, ANLS, Relaxed Accuracy) and aggregate final results.
\end{enumerate}
This unified pipeline ensures a consistent evaluation procedure across all compared models.

\section{Datasets}
We evaluate three text-centric VQA benchmarks: \textbf{TextVQA}, \textbf{DocVQA}, and \textbf{ChartQA}.

The goal is to measure whether the model can \textbf{read textual content in images, understand questions, and perform basic reasoning} across different visual domains \cite{singh2019vqamodelsread,mathew2021docvqadatasetvqadocument,masry2022chartqabenchmarkquestionanswering}.

These datasets are selected because they require OCR-heavy understanding, cover complementary visual domains, and include retrieval, layout understanding, and numerical reasoning \cite{singh2019vqamodelsread,mathew2021docvqadatasetvqadocument,masry2022chartqabenchmarkquestionanswering}.

\subsection{Dataset Descriptions}
\textbf{TextVQA} \cite{singh2019vqamodelsread}: evaluates question answering on natural images containing scene text.  
It focuses on reading text in-the-wild and combining it with question understanding.
\textit{Sample question}: ``What word is written on the stop sign?''
\textit{Sample answer}: ``No word is visible on this sign.''

\section{Training Configuration}

Unless otherwise stated, the main distillation experiments use a shared training
configuration so that differences in performance can be attributed to the
distillation strategy rather than unrelated optimization choices.

All training runs are executed on a single \textbf{NVIDIA A100 80GB} GPU using
the \textbf{Modal} runtime environment. Distillation training uses
\textbf{DeepSpeed ZeRO Stage 2}, \textbf{bf16} mixed precision, \textbf{TF32}
matrix multiplication, and gradient checkpointing to control memory use while
keeping the student fully trainable and all teachers frozen
\cite{rajbhandari2020zero,chen2016sublinear}.

Before training, all benchmark samples are converted into a unified
\textbf{LLaVA-style multimodal instruction format}
\cite{liu2023visualinstructiontuning}. Each example is stored as an image plus
a short user-assistant dialogue, so TextVQA, DocVQA, and ChartQA can share the
same data loader, prompt template, and answer supervision interface.

Listing~\ref{lst:llava-format} shows the structure used in our preprocessing
pipeline.

\section{Evaluation Metrics}
We report benchmark-specific official metrics for each dataset:
\begin{itemize}
\item \textbf{TextVQA}: \textbf{VQA Accuracy}. For a predicted answer \(\hat{a}\), the per-question score is
\[
s_{\text{VQA}}=\min\left(\frac{\#\text{annotators that provided } \hat{a}}{3},\,1\right),
\]
and the final score is the mean over all questions \cite{singh2019vqamodelsread}.

\item \textbf{DocVQA}: \textbf{ANLS} (Average Normalized Levenshtein Similarity):
\[
\mathrm{NLS}(a,\hat{a})=1-\frac{d_{\text{Lev}}(a,\hat{a})}{\max(|a|,|\hat{a}|)}, \quad
s_{\text{ANLS}}=
\begin{cases}
\mathrm{NLS}(a,\hat{a}), & \mathrm{NLS}\ge 0.5,\\
0, & \text{otherwise}.
\end{cases}
\]
The final ANLS is the average score over all samples \cite{mathew2021docvqadatasetvqadocument}.

\item \textbf{ChartQA}: \textbf{Relaxed Accuracy}. A prediction is correct if it matches exactly for text answers, or if the relative error is within \(5\%\) for numeric answers:
\[
\frac{|\hat{y}-y|}{|y|}\le 0.05.
\]
The final score is the proportion of correct predictions \cite{masry2022chartqabenchmarkquestionanswering}.
\end{itemize}

\section{Baselines and Compared Methods}
\noindent
For consistency with Chapter~\ref{chap:experiment-results}, we organize the
compared methods into four groups: non-distillation references, same-family
distillation baselines, different-family single-teacher baselines, and
heterogeneous multi-teacher baselines.

\begin{itemize}
\item \textbf{Non-distillation references.} The original student and the full-finetuning baseline provide the student-only reference points for each benchmark.
\item \textbf{Same-family baselines.} Forward KL, reverse KL, Jensen-Shannon divergence, and HSM-CKA all use \textbf{SmolVLM2-2.2B-Instruct} as a same-family teacher \cite{smolvlm2_modelcard,marafioti2025smolvlm,hinton2015distillingknowledgeneuralnetwork,lin1991jensen,dasgupta2025improving,cui2024sinkhorn}. They isolate standard teacher-student transfer when tokenizer, vocabulary, and output space are already matched.
\item \textbf{Different-family single-teacher baselines.} This group uses one teacher outside the SmolVLM family. ULD is the main cross-tokenizer logits baseline \cite{boizard2024towardscrosstokenizerdistillation}, while the layer-wise hidden-state baseline tests whether direct internal matching remains useful across heterogeneous VLM families \cite{dasgupta2025improving}.
\item \textbf{Heterogeneous multi-teacher baselines.} Uniform averaging, reinforced selection, and \methodname{} all use teacher pools drawn from different VLM families. Uniform averaging keeps fixed equal weights, reinforced selection learns a stochastic teacher policy with REINFORCE \cite{williams1992simple,yuan2020reinforcedmultiteacherselection}, and \methodname{} uses sparse routing plus alignment-aware reweighting \cite{zhang2023adaptivemultiteachermetalearning,yu2024selectdistill}.
\end{itemize}

For the trainable competitor methods, we use a shared supervised term
\(\mathcal{L}_{CE}\) and vary only the distillation component. A convenient
generic form is
\begin{equation}
\mathcal{L}_{\text{base}}=(1-\alpha)\mathcal{L}_{CE}+\alpha \mathcal{L}_{KD}.
\end{equation}

\noindent
The compared objectives are:
\begin{itemize}
\item \textbf{Original}: direct evaluation of the released student, with no additional optimization. This measures the native capability of the compact model before any task adaptation or distillation.
\item \textbf{Full finetuning}: \(\mathcal{L}=\mathcal{L}_{CE}\). This baseline uses only ground-truth supervision and no teacher, so it isolates the benefit of external teacher knowledge.
\item \textbf{Forward KL}: this is the standard logits-based KD baseline, where the student matches the teacher soft distribution over the shared vocabulary \cite{hinton2015distillingknowledgeneuralnetwork}. It is appropriate for same-family transfer because both models use compatible token spaces:
\[
\mathcal{L}_{KD}=\mathrm{KL}(p_t\|p_s).
\]
\item \textbf{Reverse KL}: this baseline swaps the divergence direction and penalizes student probability mass that falls outside the teacher support. In KD studies, it is often treated as a sharper, more mode-seeking alternative to forward KL \cite{cui2024sinkhorn,wen2023fdistill}:
\[
\mathcal{L}_{KD}=\mathrm{KL}(p_s\|p_t).
\]
\item \textbf{Jensen-Shannon}: this baseline symmetrizes forward and reverse KL by comparing both distributions to their midpoint. It is a standard compromise when one wants a bounded and symmetric divergence on the same token space \cite{lin1991jensen,cui2024sinkhorn}:
\[
\mathcal{L}_{KD}=\tfrac{1}{2}\mathrm{KL}(p_s\|m)+\tfrac{1}{2}\mathrm{KL}(p_t\|m),\qquad
m=\tfrac{1}{2}(p_s+p_t).
\]
\item \textbf{HSM-CKA}.\par
This baseline adds linear-CKA hidden-state matching to same-family logits KD \cite{dasgupta2025improving,kornblith2019similarityrepresentations}:
\[
\mathcal{L}=(1-\alpha)\mathcal{L}_{CE}+\alpha \mathcal{L}_{\text{Fwd-KL}}+\lambda_H\!\left(1-\sqrt{\mathrm{CKA}(H_s,H_t)}\right).
\]
\item \textbf{ULD}: this is the main cross-family logits baseline. Rather than aligning token IDs directly, it sorts the probability mass and compares ranked distributions, which makes it suitable when the teacher and student have different vocabularies or tokenizers \cite{boizard2024towardscrosstokenizerdistillation}:
\[
\mathcal{L}_{KD}=\left\|\pi(p_s)-\pi(p_t)\right\|_1.
\]
\item \textbf{Layer-wise hidden-state loss}: this baseline extends hidden-state matching across multiple intermediate layers and tests whether explicit internal alignment is sufficient in the heterogeneous setting. It keeps the logits objective but adds representation terms over selected layers \cite{dasgupta2025improving}:
\[
\mathcal{L}
=(1-\alpha)\mathcal{L}_{CE}
+\alpha \mathcal{L}_{KD}
+\lambda_H \sum_{\ell}\left(1-\sqrt{\mathrm{CKA}(H_s^{(\ell)},H_t^{(\ell)})}\right).
\]
\item \textbf{Uniform multi-teacher}: this baseline uses the same heterogeneous teacher pool as \methodname{}, but removes all adaptivity. Each teacher contributes equally, so it tests whether teacher diversity alone is sufficient without routing or selection \cite{yuan2020reinforcedmultiteacherselection,zhang2023adaptivemultiteachermetalearning}:
\[
\mathcal{L}_{KD}=\frac{1}{M}\sum_{i=1}^{M}\mathcal{L}_{KD}^{(i)}.
\]
\item \textbf{Reinforced selection}: this baseline keeps the multi-teacher setting but replaces deterministic routing with a stochastic teacher-selection policy. The selector predicts Bernoulli probabilities, samples a subset, normalizes the selected teachers, and is optimized with a REINFORCE-style reward signal \cite{williams1992simple,yuan2020reinforcedmultiteacherselection}:
\[
\pi_i=\sigma(u_i),\qquad
m_i\sim\mathrm{Bernoulli}(\pi_i),\qquad
w_i=\frac{m_i}{\sum_j m_j},
\]
then uses
\[
\mathcal{L}_{KD}=\sum_{i=1}^{M} w_i \mathcal{L}_{KD}^{(i)}, \qquad
\mathcal{L}=(1-\alpha)\mathcal{L}_{CE}+\alpha\mathcal{L}_{KD}+\lambda_{\text{pol}}\mathcal{L}_{\text{pol}},
\]
with a policy term \(\mathcal{L}_{\text{pol}}=-A\log p(m\mid \pi)\) and a fallback to the highest-probability teacher when \(\sum_i m_i=0\).
\end{itemize}

Unless noted otherwise, all baselines reuse the same data conversion pipeline,
hardware, optimizer family, and checkpointing protocol described earlier in
this chapter. Methods that do not use routing simply omit the GRACE-specific
terms and retain the corresponding single-teacher or uniform multi-teacher
objective from the cited source.
